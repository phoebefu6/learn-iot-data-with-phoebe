Reading a turbofan run as a dataset

Every practitioner session works on one file: NASA's FD001 training set, 100 simulated turbofan engines, each recorded once per cycle from a healthy start to failure. Tonight reads it the way a careful analyst reads any new table: what each column is, which ones carry nothing, how the rows are grouped, and where the label is. The label is the surprise. It is not a column. It is the number of cycles left, and it only exists because each engine was run until it broke. Real public rows from NASA's simulation, decoded in your browser.

Part 0

Harrow Lane's analyst opens the file

Harrow Lane Overhaul is a constructed engine-overhaul shop, and its fleet is NASA's 100 simulated engines. Its analyst has loaded tables for a decade: orders, sessions, invoices. She opens the training file expecting a fact table with a target column. She finds 26 columns of numbers, separated by spaces, no header, no nulls and no target. Every practitioner session after this one builds on what she works out in the next 45 minutes.

★ What you walk out with tonight. The FD001 training file read column by column, with the 21 sensor channels named and placed. The 7 channels that never move in it, and why. The grain of the table: one row per engine per cycle, 20,631 rows, lives from 128 to 362. The remaining-useful-life label computed from the cycle count, which is only possible because every training engine ran to failure. And the first model anyone should ship, the fleet average, scored on 300 held-out cut points: it misses by 45.61 cycles on average (root mean square).

LiveWhere the file comes from3 min▶

NASA's Prognostics Center of Excellence publishes a data set repository; this is data set 6, "Turbofan Engine Degradation Simulation", cited as Saxena and Goebel (2008). The zip holds four subsets. FD001 is the simplest: 100 training and 100 test trajectories, one operating condition (sea level), one fault mode (high-pressure compressor degradation). The others add six operating conditions, a second fault mode, or both.

The engines are simulated with C-MAPSS, so every page that quotes these rows calls them what they are: real public rows from NASA's simulation, not real engines. That is a strength for learning. The truth is recorded, the fleet is large, and every engine was allowed to do what real ones are maintained to avoid: fail.

Self-studyThe words that keep coming back3 min▶
  • Unit. One engine. Column 1. The nearest thing to an id, and it identifies a machine, not a person.
  • Cycle. Column 2, counting from 1. One row per cycle; time is in cycles, never in clock time.
  • Operational settings. Columns 3 to 5. In FD001 the third is constant at 100.0 and the first two only jitter.
  • Sensor channels. Columns 6 to 26, sensor measurements 1 to 21.
  • Run to failure. Training engines end at failure. Test engines stop some time before it.
  • Remaining useful life (RUL). Cycles left before failure. Computed, not recorded.
  • Held-out engines. 30 training engines set aside by a seeded split, cut at 10 points each, to score models. They stand in for the NASA test set on every page.
Part 1 · covers the file

Twenty-six columns and no target

12 min live

The readme lists the columns in plain words: unit number, time in cycles, three operational settings, and 21 sensor measurements. It does not name the sensors; the paper's Table 2 lists 21 sensed outputs in an order that the field pairs with sensor 1 to 21. The figure draws the two halves of the data side by side, because the difference between them is where the label comes from.

LiveThe 21 channels, named4 min▶

Table 2 of Saxena, Goebel, Simon and Eklund (2008) lists the 21 sensed outputs with their units: four temperatures (T2 at the fan inlet, T24 at the low-pressure compressor outlet, T30 at the high-pressure compressor outlet, T50 at the low-pressure turbine outlet) in degrees Rankine; four pressures (P2, P15 in the bypass duct, P30 and the static Ps30) in psia; four shaft speeds (physical Nf and Nc, corrected NRf and NRc) in rpm; and nine more: engine pressure ratio, fuel flow over Ps30 (phi), bypass ratio, burner fuel-air ratio, bleed enthalpy, the two demanded fan speeds, and the two turbine coolant bleeds W31 and W32.

The readme numbers the sensor columns 1 to 21 and does not name them. Pairing sensor 1 with T2 and sensor 21 with W32 follows Table 2's order, and it is the convention the prognostics literature uses; treat the pairing as reported, not as something the file itself states.

Real world

Harrow Lane's analyst wrote the 21 names into a header row before doing anything else, then sorted them by where the probe sits in the engine. Four columns she had been about to call "redundant" (the physical and corrected fan and core speeds) turned out to be two shafts, each read two ways. Naming before modelling saved her from reading the same signal twice as two pieces of evidence.

LiveThe seven that never move4 min▶

Computed on all 20,631 training rows: sensors 1 (T2), 5 (P2), 10 (epr), 16 (farB), 18 (Nf_dmd) and 19 (PCNfR_dmd) take exactly one value each; sensor 6 (P15) takes two, 21.60 and 21.61. Operational setting 3 is constant at 100.0. FD001 runs at one condition, sea level, so the fan-inlet conditions and the demanded speeds do not change.

They are dropped from the shipped sample and listed in it, so the fact travels with the data. They are not dropped because they are broken. In the six-condition subsets they move with the operating regime, which is exactly why a model trained on FD001 cannot be carried to FD002 without work.

Self-studyWhere serious people disagree4 min▶

Once the label is computed, the first modelling choice is whether to use it as it is. An engine at cycle 1 with 191 cycles left looks, in its sensors, almost exactly like the same engine at cycle 60 with 132 left: nothing has started to degrade. Many papers therefore cap the label, holding it constant early in life and letting it fall only near the end.

They do not agree on the cap. One recent paper sets it at 130 ("We use piece-wise linear RUL as the target function, where the maximal RUL is 130"); another sets it at 125 "based on the minimum run length of 128 cycles observed in the training data"; a survey adopts 125 citing earlier work. The paper usually credited with the idea, Heimes (2008), was not read here; its value is reported second-hand only. Practitioner session 5 runs both and shows the difference. It is a convention, chosen on this subset, not a law of engines.

Part 2 · covers the label

The label hiding in the cycle count

12 min live

For a training engine of life n, the row at cycle t has n minus t cycles left. Engine 1 runs 192 cycles, so its first row carries 191 and its last row carries 0. Drawn against cycle, that label is a straight line down to failure; the capped version is flat at the cap and then the same line. The inspector below decodes any row of any engine and prints both.

LiveReading the inspector4 min▶

Leave it on engine 1, cycle 1: remaining life 191, capped 125. Slide to the last cycle and the label reaches 0. Now watch T50 as you slide: it sits near 1400 for most of the life and climbs only in the last few dozen cycles. The capped label is a statement about that fact: early in life there is nothing in the channels to separate 191 from 132, so a model is not asked to.

The values are quantised: each channel was stored at no more than 90 levels so that all 20,631 rows fit in a page. T50 keeps a step of 0.67 degrees Rankine, the core speed Nc 2.50 rpm. Engine 1's first exhaust reading is 1400.60 in the original file and 1400.89 here. That precision is far finer than the channel's cycle-to-cycle noise, and it is stated so nobody mistakes the sample for the original.

LiveThe first model, and its first score4 min▶

The simplest honest model ignores the sensors. Take the 70 training engines of the seeded split, average their lives (200.37 cycles), and predict "200.37 minus the cycles seen so far", floored at zero. Score it on 30 held-out engines cut at 10 random points each, 300 units under test. Its root mean square error is 45.61 cycles.

That number is the floor every later model has to beat. Practitioner session 7 shows why its other score, the asymmetric one, is enormous (305,167 summed over the 300 units): two long-lived engines are already past the average at their cut points, so the baseline tells the planner they are about to fail when 140 cycles remain.

Self-studyWhy the held-out engines, not the NASA test set3 min▶

The NASA test file and its true-RUL file would push the page's data past 300 KB, so the sample ships the 100 training engines only. A seeded split (seed 2008) sets 30 aside; each gets 10 cut points with true remaining life drawn uniformly from 10 to 150 cycles (or less for engines too short to allow it), mirroring the PHM08 test range of 10 to 150 that the paper reports.

The consequence: scores here are not comparable to published FD001 test-set results, and no page compares them. They are comparable to each other, which is what the ladder needs.

Part 3 · build-along

Load the fleet, count it, label it, score the floor

18 min hands on

Open the browser console on this page (the sample and the engine are already loaded). Six steps, each with the number you should see. The figure shows what happened to the file before it reached your console, so you know exactly what you are reading.

Decode the fleet

IOT.decode turns the sample back into numbers: one object per engine with its life n, its rows (one array of 14 channel values per cycle) and its cycle numbers. You should see 100.

consolevar units = IOT.decode(IOT_SAMPLE); units.length

Count the rows and the lives

20,631 rows; the shortest life 128 (engine 39), the longest 362 (engine 69). The mean over all 100 is 206.31.

consolevar lives = units.map(function (u) { return u.n; }); [lives.reduce(function (a, b) { return a + b; }, 0), Math.min.apply(null, lives), Math.max.apply(null, lives)]

List what moves and what was dropped

Fourteen channels in channel order, and the seven flat ones with their Table 2 symbols. Write the second list into your notes; it is a fact about this operating condition.

consoleIOT_SAMPLE.channels.join(" "); IOT_SAMPLE.flat.map(function (f) { return f.ch + " " + f.sym; })

Read one channel's precision

The metadata says where each channel starts and how big one step is. T50 (s4) starts at 1382.25 with a step of 0.665618; its original column held 4,051 distinct values.

consoleIOT_SAMPLE.meta.s4

Compute the label for engine 1

Remaining life is life minus cycle. The first three rows carry 191, 190 and 189; the last carries 0. Cap it at 125 and the first rows all read 125.

consolevar u = units[0]; var rul = u.cyc.map(function (c) { return u.n - c; }); [rul.slice(0, 3), rul[rul.length - 1], Math.min(rul[0], 125)]

Score the floor

The fleet-average model on the 300 held-out cut points, seed 2008. You should see a root mean square error of 45.61 and a training mean life of 200.37; your numbers will match for the same seed.

consolevar r = IOT.ladder(IOT_SAMPLE, { only: ["mean"] }); [r.mean.rmse.toFixed(2), r.mean.meanLife.toFixed(2), r.mean.n]

The habit to keep. Before any model, write four lines: the grain (one row per engine per cycle), the columns that never move and why, where the label comes from, and the floor a model with no sensors scores. Every claim after that is a claim against those four lines.

Check yourself

Three questions

Where does the remaining-useful-life label for a training row come from?

The file has no target column and the health index was never given out. The label is derived, and the derivation depends on the failure being in the file, which is exactly what the test set withholds.

Sensor 6 (P15, bypass-duct pressure) takes only the values 21.60 and 21.61 across 20,631 FD001 rows. What is the right treatment?

Two values a hundredth apart is resolution, not information. Nothing says the probe failed. And in the six-condition subsets the bypass pressure moves with the regime, so "flat here" must not become "drop everywhere".

The fleet-average model scores a root mean square error of 45.61 cycles on the 300 held-out cut points. What is that number for?

The held-out engines are a seeded stand-in for the test set, so the number is not comparable to published results. Its job is to be the score of knowing nothing about the engine but its age.

Before session 2

Homework

Thirty minutes, in the console on this page.

Find the engine that looks oldest at birth

For every engine, average T50 over its first 20 cycles. Which engine starts hottest, and how long did it live? (Engine 39 starts at 1407.14 and lives 128; check whether any engine beats it.) Write one sentence on what that says about using an absolute temperature threshold.

Write the four lines for a dataset you own

Grain, silent columns, where the label comes from, and the floor. If the label is "an event that happened later", say how long you had to wait for it, which is session 2's question about clocks.
